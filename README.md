# Green API Test

Чат на React и TypeScript с Vite и GREEN API: авторизация, проверка номера,
история переписки, отправка сообщений и получение уведомлений.

Интеграция нацелена на работу с Telegram через GREEN API.

## Запуск

```bash
npm install
npm run dev
```

Введите `idInstance` и `apiTokenInstance` своего инстанса. После ответа
`authorized` данные сохраняются в `localStorage` и повторно проверяются при
загрузке страницы. Номер собеседника вводится с кодом страны, только цифрами.
`chatId` для истории и отправки берётся из ответа `checkAccount`.
Кнопка «Выйти» на экране выбора номера и в шапке чата удаляет сохранённые
данные инстанса и возвращает на вход, где можно указать другие данные.

## Маршруты

- `/login` — авторизация.
- `/chats/new` — выбор номера собеседника.
- `/chats/:chatId?phone=79991234567` — переписка с указанным `chatId`.

Экраны чата доступны после проверки авторизации. Прямую ссылку на чат можно
открыть или обновить: данные чата берутся из URL, данные инстанса — из сохранённой
сессии. После входа приложение возвращает пользователя на запрошенный экран.
Параметр `phone` используется только для отображения номера в шапке; API получает
`chatId` из пути. Секреты инстанса в URL не передаются.

Для размещения на статическом хостинге нужно настроить возврат `index.html`
для маршрутов приложения. Dev-сервер Vite и `npm run preview` поддерживают это.

## GitHub Pages

Публикация настроена через `.github/workflows/pages.yml`: при отправке в `main`
выполняются тесты, проверка типов, сборка и развёртывание `dist`.
В настройках репозитория **Settings → Pages → Source** нужно выбрать **GitHub Actions**.
GitHub Pages должен быть доступен для репозитория на текущем тарифе GitHub.

Адрес после публикации: https://zuarel.github.io/green-api-test/.

Для GitHub Pages используется отдельная сборка:

```bash
npm run build:pages
npm run preview
```

В этой сборке пути к ресурсам начинаются с `/green-api-test/`, а маршруты
используют `HashRouter`, например `/green-api-test/#/login`. Это позволяет
открывать прямые ссылки и обновлять страницы без серверной настройки SPA.
Локальный запуск и обычная сборка продолжают использовать `BrowserRouter`.

## Проверки и сборка

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`build` также проверяет типы. Тесты используют встроенный раннер Node.js
и подставные ответы API; для запуска тестов нужен Node.js 22.18+.
Проект проверен на Node.js 26.

## Структура

```text
src/
  api/          — общий клиент GREEN API, URL, JSON, таймауты и HTTP-ошибки
  components/   — формы и интерфейс чата
  hooks/        — авторизация, проверка номера, история, отправка и уведомления
  pages/        — страницы входа, выбора номера и чата
  routing/      — пути и защита маршрутов
  lib/          — хранение данных, преобразование сообщений и обработка ошибок
  services/     — цикл получения и удаления уведомлений с повторными попытками
  styles/       — общие CSS Modules для форм и базовые глобальные стили
  types.ts      — типы ответов API и моделей приложения
  App.tsx       — конфигурация маршрутов React Router
tests/          — тесты API-клиента, хранилища и обработки уведомлений
```

Компоненты вызывают хуки, хуки используют API-клиент. Только модуль
`credentialsStorage` обращается к `localStorage`. Уведомление хранится в памяти
до успешного удаления по `receiptId`, затем добавляется в текущий чат.
История и уведомления объединяются по `idMessage`, без дублирования сообщений.
Запросы отменяются при выходе с экрана.

Стили интерфейса подключаются через CSS Modules (`*.module.css`). Общие стили
форм находятся в `styles/Auth.module.css`, стили чата — рядом с компонентом.
В `styles/global.css` оставлены только базовые стили страницы.
